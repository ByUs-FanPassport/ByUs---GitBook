# GIWA integration overview

ByUs uses GIWA Sepolia to make issued Fan Passport and Live Stamp credentials publicly verifiable.

## Why the integration exists

Fan activity normally remains inside a platform account. ByUs separates two responsibilities:

| ByUs operational layer | GIWA credential layer |
| --- | --- |
| Identity, activity, score, eligibility, claims, and CRM | Passport and Stamp ownership |
| Fast product reads and writes | Public transaction and token verification |
| Private fan and fulfillment data | PII-free metadata URI |
| Business rules and retry state | Immutable issuance event |

This gives fans a durable credential record without publishing the full fan profile on-chain.

## Current integration

- Network: GIWA Sepolia
- Chain ID: `91342`
- Currency: test ETH
- Passport: soulbound ERC-721
- Stamp: soulbound ERC-1155
- Transaction model: service-relayed asynchronous minting

{% hint style="info" %}
GIWA Sepolia is the GIWA test network connected to Ethereum Sepolia. No real assets are used. See the official [GIWA network configuration](https://docs.giwa.io/giwa-chain/en/get-started/connect-to-giwa).
{% endhint %}

## Consumer activity generated by ByUs

The current product creates repeatable on-chain credential events from consumer actions:

- first creator-specific fan verification;
- LIVE reservation;
- LIVE attendance confirmed with a Fan Code;
- post-LIVE survey completion.

The application does not send a transaction for every UI interaction. It creates a credential only when the configured business rule produces a Passport or Stamp issuance.

## What the integration does not claim

- It is not a GIWA mainnet deployment.
- It is not a transferable NFT marketplace.
- It does not store all fan data on-chain.
- It does not prove that every product action is gas-sponsored.
- It is not a public API or SDK contract.

# Fan Score and benefits

Fan Score measures verified participation inside a creator-specific Passport.

## Score values

| Verified action | Score |
| --- | ---: |
| Pass fan verification | `+1` |
| Reserve a LIVE | `+1` |
| Confirm attendance with a Fan Code | `+3` |
| Complete the post-LIVE survey | `+2` |

## Fan levels

| Level | Fan Score |
| --- | ---: |
| Bronze | `0–4` |
| Silver | `5–9` |
| Gold | `10–19` |
| Platinum | `20–34` |
| Diamond | `35+` |

Levels are calculated off-chain from the fan's verified activity. They are not separate transferable tokens.

## Benefit eligibility

A benefit can combine:

- minimum Fan Score;
- minimum fan level;
- a required Stamp;
- a required fan activity;
- claim start and end time;
- remaining inventory.

Eligibility is evaluated server-side against the owning fan's current Passport context.

## Delivery modes

The current benefit domain supports experiences such as:

- immediate claims;
- application and selection;
- shared codes;
- unique codes;
- external links;
- instructions or fulfillment text.

Sensitive delivery values are stored separately from the public benefit catalog and returned only to the owning claimant.

{% hint style="info" %}
Benefit claims and delivery details remain off-chain. GIWA proves issued Passport and Stamp credentials; it does not publish private fulfillment data.
{% endhint %}

## Product principle

> A fan unlocks value through verified participation, not by moving a transferable asset or presenting a follower count.
